# Skill Match
你不记得所有的技能,所以要问.

**流程** 是实现技能的方法. 大多数方法沿着一条 **主流程**, 两条 **on-ramps** 汇入其中. 其他都是独立的流程.


## 主流程: 想法 -> 载具

大多数任务的主线. 你有一个想要达成的想法.

1. **`/grill-with-docs`** - 通过访谈来完善这个想法. 如果你**已有代码库**,请从这里开始:该系统是带状态的,会将学习到的内容保存在 `CONTEXT.md` 和 ADR 中. (如果没有代码库? 请使用 `/grill-me` —— 参见"独立模式".)

2. **分支——你能通过对话解决所有问题吗?** 如果某个问题需要可运行的答案(状态、业务逻辑、必须查看的用户界面）,请通过原型设计进行绕行,并利用 **`/handoff`** 在两个方向上进行衔接(参见“跨会话”):
  - **`/handoff`** 退出，然后针对该文件打开一个新的会话,
  - **`/prototype`** 用伪代码回答问题,
  - **`/handoff`** 总结你学到的内容,并在原始创意帖中引用它.

3. **分支——这是多会话的构建吗？**
  - **是** -> **`/to-prd`**(将该思路转换为 PRD) -> **`/to-issues`**(将 PRD 拆分为可独立处理的议题).由于这些问题是独立的，请**明确每个问题之间的上下文**:针对每个问题启动一个新的会话，并通过传入PRD和待处理的单个问题来启动**`/implement`**。
  - **没有** → **`/implement`** 此处(同一上下文窗口中).

### 上下文维护

请将步骤 1–3 保存在**一个完整的上下文窗口**中——在执行 `/to-issues` 之前不要压缩或清空该窗口——这样,需求梳理、产品需求文档(PRD)和问题单都能基于相同的思路展开.随后,每次执行 `/implement` 时都应从头开始,以问题单为依据展开工作.

这方面的限制是 **[智能区](https://www.aihero.dev/ai-coding-dictionary/smart-zone)**:模型仍能清晰推理的窗口(在最先进的模型上约为 12 万个 token).如果一个会话在 `/to-issues` 之前接近这个限制,不要在退化的情况下继续操作 — 使用 `/handoff` 并在新的线程中继续.

## On-ramps

一种会产生工作负载的初始状态,随后并入主流程.

- **问题和需求不断积累** -> **`/triage`**. 该流程会将问题在分拣角色之间流转,并生成可供处理的问题,随后由 **`/implement`** 接手处理.

分类仅适用于**非您创建的**问题——包括错误报告、新提交的功能请求,以及任何未经处理的原始问题. 由 `/to-issues` 生成的issues已经准备好交由处理人员处理,因此**请勿对它们进行分类**.

## 代码基础健康

不是功能开发——而是维护工作.

- **`/improve-codebase-architecture`** —— 只要有空闲时间就运行一下,以确保代码库始终处于适合代理运行的状态. 它会揭示进一步优化的机会; 选择其中一个 _生成的想法_, 你可以将其纳入 `/grill-with-docs` 的主流程中.

## 跨会话

- **`/handoff`** —— 当线程已满或需要分支（例如进入 `/prototype` 会话）时，此操作会将对话压缩为一个 Markdown 文件。你不会在原地继续——而是**开启一个新会话并引用该文件**，以此传递上下文。这是连接不同上下文窗口的桥梁，支持双向传输。当你希望开启一个**全新的会话**，但又需要**保留当前对话内容**时，请使用此功能。

- **`/compact`**（内置命令）——留在**同一对话**中，将之前的对话内容进行总结。请在**各阶段之间的有意中断处**使用该命令，此时您不介意丢失逐字对话记录。请勿在阶段中途使用该命令——否则对话机器人可能会迷失方向。`/handoff`会分流；`/compact`则继续当前对话。
